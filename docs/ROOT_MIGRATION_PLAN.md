# ModuForge 安全なルート再構成計画

作業ブランチ: `refactor/safe-root-layout`。現時点で本番の `main` と `FW33/` は変更しません。

## 実行順
1. `python scripts/restructure_safe.py` — 読み取り専用でファイル数と衝突を調査します。
2. 衝突ゼロを確認後、`python scripts/restructure_safe.py --stage` — **元リポジトリの隣に** `ModuForge_staging/` を新規作成してコピーします。既存の同名ステージング先には一切上書きしません。
3. ステージング内で BAT の相対パス、Python import、アセット参照、依存関係、ライセンス、試験ランナーを修正します。変更前後のマッピングを記録します。
4. Windows 11で既存試験・8モジュールの単体/結合/GUI/異常系試験を実施します。試験用データのみを使い、ファイル移動・復元などの危険操作は確認を必須とします。
5. 合格後に別コミットで再構成内容を作業ブランチに反映し、差分とGit履歴を確認します。
6. プルリクエストでレビュー後、`main` へマージします。

## 注意
- `--stage` は再配置したファイルの実行可能性を保証しません。特に BAT の相対パスは未修正です。
- `migration_review/` は自動分類できなかったファイルの退避先です。内容をレビューしてから正式な移動先を決めます。
- `FW33/` の削除や `git rm --cached` は、自動で実行しません。
- 元ファイルとの突き合わせ、独立性チェック、Windowsでのテストが済むまでは移行完了と見なしません。
- `ModuForge_staging/` は Git リポジトリではなく、レビュー用の作業コピーです。
