## 判定の範囲

サービスのキャンセル試験はGUI確認ダイアログの「いいえ」の試験とは別。途中停止は、処理済みファイルを戻さず残りを停止する仕様。復元は退避からのコピーであり、変更後ファイルも残す。バッチ全体の自動ロールバックは検証・保証していない。

Windowsの実際のrename挙動、大文字小文字だけの変更、ファイルロック、GUIのライト/詳細モード、選択行、確認拒否は未実施。GitHub Actionsの今回コミットに対する結果は、このローカル結果とは別に確認する。

PRはDraftのまま。mainへマージしない。旧`FW33/`とFileWorkbench Next v3.3.0-rc1を保持。

## Windows GUIの次の手順

1. 新ルートをプルして `python run_component.py rename` で開く。
2. リポジトリ外の試験フォルダーに、`sample_A.txt`、`sample_B.txt`、`new_sample_A.txt`を作成し、それぞれ異なる短い本文を入れる。実データは使わない。
3. フォルダーを指定し、ライトモードでPrefixに `new_` を入れる。既存名衝突が「自動回避」となること、本文と元ファイル名が変化していないことを確認。
4. 実行を押し、確認で「いいえ」を選ぶ。名前・本文がすべて変化していないことを確認。
5. 1行を選び「選択行だけ実行」にチェックして実行。確認された1件だけがプレビュー通りに変わることを確認。
6. 詳細モードで連番・拡張子条件を試す。ライトへ戻した際に詳細条件が適用されないことを確認。禁止文字 `?` をPrefixに入れた場合、無効な行を実行しないことを確認。
7. スクリーンショットと実際の前後の名前を記録する。結果を確認してからRecycleの一覧・フィルター試験へ進む。

Recycleの復元は独立したテストユーザー/VMで行う。現在のユーザーの実ごみ箱は試験に使わない。
